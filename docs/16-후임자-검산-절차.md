# 후임자 검산 절차 (구현 계획 11단계)

docs/06의 결론: 옛 검증 기록은 폐기된 시스템에 대한 것이므로, v2는 **처음부터 다시** 검산한다. 이 문서는 시스템을 만든 사람이 아닌 사람이, 문서만 보고 시스템의 핵심 주장을 스스로 확인하는 절차다. 각 항목은 "주장 → 확인 방법 → 통과 기준"으로 적었다. 11단계 종결 때 1회 수행하고 결과(날짜·수행자·소요 시간·막힌 지점)를 이 문서 끝에 기록한다.

## 준비 (약 10분)

```bash
git clone <저장소> && cd opencourse && pnpm install
pnpm exec playwright install chromium
```

## 검산 항목

| # | 주장 | 확인 방법 | 통과 기준 |
| --- | --- | --- | --- |
| 1 | 모든 검사가 초록이다 | `pnpm typecheck && pnpm build && pnpm test && pnpm e2e && pnpm qa:a11y` | 전부 성공, 실패 0 |
| 2 | 검수 없는 발행은 불가능하다 | `pnpm test` 출력에서 "우회 시도" 7건 확인. 추가로 손으로: 발행 교재의 `course.json` status를 직접 published로 바꾸고 `pnpm build` → 산출물에 없는지 | 우회 7건 전부 차단 + 손 우회도 산출물 제외 |
| 3 | 문장 검수자는 문장 하나만 받는다 | `packages/pipeline/src/review/review.test.ts`의 격리 단언(전문·이웃·타 판정 부재)을 읽고 실행 | 테스트가 실제로 그 부재를 단언한다 |
| 4 | 보드는 거짓말하지 않는다 | `course.json` 아무 값이나 바꾼 뒤 `pnpm board:check` | 낡은 보드로 실패한다 (되돌리고 재확인) |
| 5 | 초안은 어디에도 새지 않는다 | `pnpm e2e` 중 "초안" 관련 4건 (산출물·404·사이트맵·문맥 번들) | 전부 통과 |
| 6 | 한도·RLS는 서버가 지킨다 | `supabase start && pnpm e2e:backend` | 통합 10건 전부 통과 |
| 7 | 발행 교재가 실제로 열린다 | 공개 주소(또는 `pnpm e2e` 후 `node e2e/serve.mjs 4173`)에서 교재 열람, 영상 재생, 도우미 질문 1회 | 세 동작 모두 정상 |
| 8 | 실행 기록이 지표를 만든다 | `pnpm metrics` — 세 지표가 ops/runs 실측에서 나오는지 소스(`ops/metrics.ts`) 대조 | 지표 값과 기록 파일이 일치 |
| 9 | 열쇠 백업만으로 복구된다 | docs/13 복구 절차를 백업만 보고 수행 | 전 도구 동작 (9단계 리허설과 동일) |
