# 콘텐츠 계약 스키마

> [저장소 파일 배치](02-저장소-파일-배치.md)가 정한 파일들의 **필드 수준 설계**다. 구현 계획 1단계는 이 문서를 zod와 JSON Schema 코드로 옮기고 검증기를 만드는 일이며, 여기서 정하지 않은 필드를 코드가 임의로 만들지 않는다. v1 검수 파일의 실물 구조(`startup-idea-one-page` 교재의 검수 기록)를 2026-08-25에 조사해 계승할 것은 계승하고, 기획서가 요구한 것을 더했다. 바꾸면 이 문서를 먼저 고치고 [구현 계획](08-구현-계획.md) 변경 기록에 남긴다.

---

## 0. 공통 규약

| 규약 | 값 |
| --- | --- |
| 스키마 버전 | 모든 JSON 파일 최상위에 `schema_version: 1` (정수). 호환 깨지는 변경 시에만 올린다 |
| 필드 표기 | `snake_case` (v1 계승) |
| 시각 | ISO 8601, 오프셋 포함 (`2026-08-25T13:00:00+09:00`) |
| 파일 지문 | 커밋된 파일 바이트의 SHA-256, 소문자 64자리 16진수. 정규화 없음 — 포매터가 LF와 끝 개행을 강제한다 |
| 문장 지문 | NFC 정규화 + 앞뒤 공백 제거 + 연속 공백 1칸 축약한 문장 텍스트의 SHA-256 |
| 축약 지문 | 식별자 안에서는 지문 앞 10자리만 쓴다 |
| 교재 식별자 | `course_id`: ULID. 슬러그가 바뀌어도 불변 |
| 챕터 식별자 | 폴더명 `NN-슬러그` (NN은 01부터 2자리). 챕터 id = 폴더명 |
| 소단원 파일 | 챕터 폴더 안 `NN.mdx` (01부터) |
| 문장 단위 id | `챕터폴더/파일:서수:문장지문10` (v1 계승. 예: `01-intro/01.mdx:3:938287823b`) |
| 미디어 id | `fig-NN`(인포그래픽), `aud-NN`(음성). 챕터 안에서 유일 |
| 작업 id | `run_id`: `<종류>-<과제>-<YYYYMMDDHHmm>` (예: `gen-flexbox-202608251300`) |
| 상태 열거값 | 교재: `generating / draft / published / hidden`. 검수 등급: `pass / minor / major / critical`. 기계 등급: `block / warn`. 게이트 상태: `missing / failed / stale / passed` |
| 정본 원칙 | 같은 값을 두 파일이 갖지 않는다. 교재 상태의 정본은 `course.json`뿐이고, `progress.json`은 게이트 요약만 갖는다 |

## 1. `course.json` — 교재 정보 (정본)

| 필드 | 타입 | 규칙 |
| --- | --- | --- |
| `schema_version` | int | 1 |
| `id` | string | ULID, 불변 |
| `title` | string | 필수 |
| `slug` | string | `[a-z0-9-]+`, 발행 뒤 불변. 한글 제목은 로마자 표기법으로 생성, 중복 시 `-2` 연번 |
| `summary` | string | 한 줄 설명. 목록 카드와 검색에 쓰인다 (v1 계승) |
| `topic` | string | 생성 시 입력한 주제 |
| `audience` | string | 대상 학습자 서술 |
| `difficulty` | enum | `beginner / intermediate / advanced` |
| `language` | string | BCP-47, 기본 `ko` (v1 계승) |
| `learning_outcomes` | string[] | 1개 이상 |
| `prerequisites` | string[] | 없으면 빈 배열이 아니라 "없음" 서술 1개 (v1 관례) |
| `content_style` | string | 콘텐츠 스타일 서술 |
| `status` | enum | `generating / draft / published / hidden` |
| `created_at` / `updated_at` | datetime | |
| `published_at` | datetime\|null | 최초 발행 확정 시각. 숨겨도 지우지 않는다 |
| `style_version` | string | 생성에 적용한 스타일 버전 (예: `v1`) |
| `estimated_minutes` | int | 전체 예상 학습 시간 |
| `edit_count` | int | 초안 등록 뒤 본문 저장 횟수 계수기 |
| `rewrite_after_publish_count` | int | 발행 뒤 내용 누락으로 다시 쓴 횟수 계수기 |
| `chapters[]` | object[] | 아래 |
| `chapters[].id` | string | 폴더명과 동일 (`01-intro`) |
| `chapters[].title` / `summary` | string | 목차에 표시 |
| `chapters[].estimated_minutes` | int | |
| `chapters[].outcomes` | string[] | |
| `chapters[].subchapters[]` | object[] | `{ file: "01.mdx", title }` 순서 = 배열 순서 |
| `generated_by` | object | `{ run_id, style_version }` 생성 이력 참조 |

소단원 MDX의 프런트매터는 `{ title, summary }` 둘만 갖는다. 본문 안 미디어는 **식별자로만 참조**한다(표기 문법은 1단계 구현에서 확정하되, R2 URL을 본문에 직접 쓰는 것은 계약 위반이다).

## 2. `chapters/<NN-슬러그>/media.json` — 챕터 미디어 목록

| 필드 | 타입 | 규칙 |
| --- | --- | --- |
| `schema_version` | int | |
| `chapter_id` | string | |
| `items[]` | object[] | 미디어 하나당 하나 |
| `items[].id` | string | `fig-NN` / `aud-NN` |
| `items[].kind` | enum | `infographic / audio` |
| `items[].alt` | string | 인포그래픽은 필수 (없으면 기계 검사 ST10 차단) |
| `items[].source` | string | 원본 산출물 경로 (`ops/runs/<run_id>/...`) |
| `items[].r2_key` / `url` | string | S11에서 기록. 업로드 전에는 null |
| `items[].bytes` / `sha256` | int / string | 업로드한 파일 기준 |
| `items[].uploaded_at` | datetime\|null | |
| `items[].status` | enum | `active / cleanup`. 교체되면 새 항목 추가 + 옛 항목 `cleanup` |
| `items[].cleanup_marked_at` | datetime | `cleanup`일 때 필수. 90일 규칙의 기준 시각 |
| `video` | object | `{ audio_item: "aud-01", timeline_file: "timeline.json", captions_file: "captions.vtt", duration_sec }` — `duration_sec ≤ maxOverviewSeconds` |

### `timeline.json` — 영상 타임라인 (같은 폴더)

`{ schema_version, chapter_id, gap_sec: 2, total_duration_sec, scenes[] }`.
장면: `{ index, start_sec, duration_sec, narration, visual }`. `visual`은 `{ type: "title" | "bullets" | "figure" | "diagram" | "code", ... }` 형태의 태그된 유니언이며 세부 속성은 1단계에서 Remotion 컴포넌트와 함께 확정한다. `start_sec`은 음성 길이 실측으로 계산된 값이지 추정값이 아니다. 자막은 표준 WebVTT(`captions.vtt`).

## 3. `review/progress.json` — 게이트 요약

교재 상태는 담지 않는다(정본은 `course.json`).

```json
{
  "schema_version": 1,
  "course_id": "…",
  "gates": {
    "machine_check":  { "state": "passed", "checked_at": "…" },
    "sentence_review": { "state": "failed", "round": 2, "clean_pass_at": null },
    "section_review":  { "state": "missing" },
    "manual_review":   { "state": "passed", "open_blockers": 0 }
  },
  "fingerprints_ok": true,
  "next_actions": ["문장 검수 3회차를 시작한다"],
  "updated_at": "…"
}
```

`state`는 `missing / failed / stale / passed`. `stale`은 판정은 있으나 지문이 어긋난 상태다. 이 파일은 도구가 재계산해 쓰는 **파생 요약**이며, 판정의 근거는 언제나 아래 개별 검수 파일이다.

## 4. `review/machine-check.json` — 기계 검사 (신설)

| 필드 | 타입 | 규칙 |
| --- | --- | --- |
| `schema_version` / `course_id` / `checked_at` | | |
| `pass` | bool | `blocker_count == 0` |
| `blocker_count` / `warning_count` | int | |
| `inputs[]` | object[] | `{ path, sha256 }` 검사한 모든 파일의 지문 |
| `standards` | object | `{ scoring_rules_sha256, manual_review_items_sha256, thresholds_sha256 }` 판정에 쓴 기준 문서 지문 |
| `defects[]` | object[] | `{ code, kind: "static"|"structure", grade: "block"|"warn", message, path, line?, detail? }` |

[채점 기준](../content/standards/scoring-rules.md)의 항목과 1:1이다. 코드는 불변이고, 새 항목은 끝 번호를 이어 쓴다.

| 코드 | 항목 | 등급 |
| --- | --- | --- |
| ST01 | 필수 항목 누락 | block |
| ST02 | 출처 주소 누락 | block |
| ST03 | 출처 확인 시각 누락 | block |
| ST04 | 사용 조건 누락 | block |
| ST05 | 표기 의무 미이행 | block |
| ST06 | 미디어 사용 사유 누락 | warn |
| ST07 | 미확인 문구 잔존 | block |
| ST08 | 채점 기준 미비 | warn |
| ST09 | 수동 검토 미해결 | block |
| ST10 | 대체 설명 누락 | block |
| ST11 | 자막·요약 누락 | block |
| SC01 | 지키지 않은 예고 | block |
| SC02 | 없는 것을 가리키는 회수 | block |
| SC03 | 시제 뒤섞임 | warn |
| SC04 | 문장 중복 | warn |
| SC05 | 용어 표기 흔들림 | warn |
| SC06 | 섹션 순서 역전 | block |

## 5. `review/sentence-review.json` — 문장 단위 격리 검수

v1 구조를 계승하고 [검수 프로토콜](../content/standards/review-protocol.md)의 회차·무효화·예외를 더한다.

| 필드 | 타입 | 규칙 |
| --- | --- | --- |
| `schema_version` / `course_id` | | |
| `protocol` | object | `{ review_protocol_sha256, beginner_baseline_sha256, thresholds_sha256 }` — 이 지문이 바뀌면 진행 중 검수 전체 무효 |
| `source_sha256` | string | 검수 대상 본문 전체의 결합 지문 |
| `status` | enum | `in_progress / revision_required / clean_pass / halted` |
| `rounds[]` | object[] | `{ round: 1..6, started_at, ended_at?, clean_pass: bool, ended_reason?: "clean_pass"|"revision"|"halted_max_rounds"|"halted_loop"|"invalidated" }` |
| `units[]` | object[] | v1 계승: `{ id, path, line, ordinal, kind: "prose"|"heading"|"list"|"quote"|"table", text, text_sha256 }`. 코드 블록·머리말 제외 |
| `reviews[]` | object[] | 문장 판정. 아래 |
| `reader_state` | object | 최신 학습자 상태 (아래) |
| `exceptions[]` | object[] | `{ unit_id, grade: "critical", reason, approved_by, approved_at }` — 심각만 예외 가능, 누적 표시용 |

`reviews[]` 원소:

```json
{
  "sentence_id": "01-intro/01.mdx:3:938287823b",
  "round": 2,
  "reviewed_at": "…",
  "state_before_sha256": "…",
  "reviewer": {
    "run_id": "sr-r2-u003-…", "model": "…",
    "fresh_context": true, "repository_access": false, "raw_neighbor_sentences": false
  },
  "dimensions": { "clarity": 2, "consistency": 2, "flow": 1, "logic": 2, "novice_comprehension": 2 },
  "severity": "pass",
  "issues": [ { "problem": "…", "suggestion": "…" } ],
  "reader_state_after": { "…": "아래 학습자 상태" },
  "invalidated": false, "invalidated_at": null, "invalidated_reason": null
}
```

**기록 거부 규칙을 스키마가 강제한다**: `reviewer`의 세 격리 플래그가 `true/false/false`가 아니거나 `model`이 비었으면 무효, `severity`가 `major/critical`인데 `issues`가 비면 무효, `dimensions`와 `severity`가 판정표와 어긋나면 무효 — 검증기가 기록을 거부한다.

**학습자 상태** (프로토콜 정본. v1의 부가 필드들은 세 목록으로 접는다):

```json
{
  "understood_facts": ["…"],        // ≤ maxKnownFacts(40)
  "defined_terms": [ { "term": "…", "definition": "…" } ],  // ≤ 40
  "open_questions": ["…"],          // ≤ maxOpenQuestions(20)
  "evictions": [ { "list": "understood_facts", "item": "…", "reason": "…", "at_unit": "…" } ]
}
```

문장별 상태 전체 사슬은 이 파일이 아니라 `ops/runs/<run_id>/learner-state.jsonl`에 남긴다(줄 하나 = 문장 하나의 상태 스냅숏). 이 파일에는 최신 상태와 판정별 `state_before_sha256`만 둔다.

## 6. `review/section-review.json` — 섹션(챕터) 전체 검수

v1 `subchapter-review.json`을 계승하되 **검수 단위가 소단원에서 챕터로** 바뀐다.

| 필드 | 타입 | 규칙 |
| --- | --- | --- |
| `schema_version` / `course_id` / `protocol` / `status` | | 문장 검수와 같은 틀 |
| `reviews[]` | object[] | 챕터 하나당 하나 |
| `reviews[].chapter_id` | string | |
| `reviews[].body_sha256` | string | 챕터 소단원 결합 지문 |
| `reviews[].context` | object | `{ prior_chapters: [{ chapter_id, body_sha256 }] }` — 앞 챕터가 바뀌면 이 판정도 무효 |
| `reviews[].reviewer` | object | `{ run_id, model, read_whole_chapter: true }` |
| `reviews[].dimensions` | object | `{ completeness, sequence, frame_consistency, evidence, learner_exit }` 각 0·1·2 (v1 계승) |
| `reviews[].severity` | enum | 판정표는 문장 검수와 같다. `major/critical`이 발행을 막는다 |
| `reviews[].missing[]` / `issues[]` / `covered[]` / `defines[]` | | v1 계승. `missing`이 이 검수의 존재 이유 |
| `reviews[].invalidated` 계열 | | 문장 검수와 동일 |
| `exceptions[]` | | 문장 검수와 동일 |

## 7. `review/manual-review.json` — 수동 검토

[수동 검토 항목](../content/standards/manual-review-items.md)과 1:1 대응하는 항목 등록부.

| 코드 | 항목 | 등급 |
| --- | --- | --- |
| MR01 | 출처가 실제로 존재하는가 (표본 5, 오류 시 전수) | block |
| MR02 | 실습·예제가 실제로 돌아가는가 | block |
| MR03 | 이미지가 본문과 맞는가 | block |
| MR04 | 음성이 본문과 맞는가 | block |
| MR05 | 저작권 판단이 필요한 자산 | block |
| MR06 | 학습 목표와 실제 내용 정합 | warn |
| MR07 | 분량 쏠림 | warn |
| MR08 | 같은 예시 반복 | warn |
| MR09 | 제목의 대표성 | warn |

```json
{
  "schema_version": 1, "course_id": "…",
  "items": [ {
    "code": "MR01", "grade": "block",
    "status": "pending" ,          // pending / done / waived
    "note": "확인한 표본과 결과",
    "waive_reason": null,           // waived면 필수 — 사유 없는 보류는 검증기가 거부
    "actor": "…", "at": "…",
    "evidence": { "sampled_source_ids": ["src-001"] }
  } ],
  "waived_count_total": 0,
  "updated_at": "…"
}
```

`grade: block`이면서 `status: pending`인 항목이 하나라도 있으면 기계 검사 ST09가 차단을 낸다.

## 8. `review/rubric.json` — 교재별 채점 기준

v1 구조 계승: `{ schema_version, course_id, artifact, grading_note, criteria[], deferred[], quality_checks }`.
`criteria[]`: `{ id: "C-1", outcome, reads[], levels: { "미달", "기준", "우수" } }`. S5에서 생성되고 스타일 버전을 `course.json.style_version`으로 추적한다.

## 9. `review/source-map.json` — 출처 목록

v1 구조 계승 + 표기 의무 필드 추가.

`sources[]`: `{ id: "src-NNN", title, publisher, url, fetched_at, http_status, license, license_url, attribution_required: bool, use_kind, use_note, used_for }`.
`sections[]`: `{ path, source_ids[] }` — 본문 인용은 여기 등록된 id만 허용(S6 규칙).
`agent_added[]` / `not_derived_from[]`: v1 계승 — 모델이 스스로 만든 구조와, 유사하지만 출처가 아닌 것의 명시.
`url / fetched_at / license` 누락은 각각 ST02·ST03·ST04 차단이다.

## 10. `content/standards/styles/` — 스타일 버전

`active.json`: `{ schema_version, active: "v1", activated_at, activated_by }`.
`v<N>.json`: `{ schema_version, version, created_at, created_by, prose: { voice, tone, terminology: [{ use, avoid, note? }] }, graphics: { palette, typography, rules[] }, narration: { voice, pace, rules[] } }`.
어느 교재가 어느 버전을 썼는지는 저장하지 않고 `course.json.style_version` 스캔으로 계산한다(정본 중복 금지).

## 11. `ops/runs/<run_id>.json` — 작업 요약

| 필드 | 타입 | 규칙 |
| --- | --- | --- |
| `schema_version` / `run_id` / `course_id` | | |
| `kind` | enum | `generate / machine-check / sentence-review / section-review / publish` |
| `started_at` / `ended_at` | datetime | |
| `status` | enum | `success / failed / aborted` |
| `failed_stage` | string\|null | |
| `stages[]` | object[] | `{ id: "S1".."S12", started_at, ended_at, status, outputs: [경로], error? }` |
| `metrics` | object | `{ model_calls?, tts_seconds?, uploaded_bytes? }` |

중간 산출물 폴더 `ops/runs/<run_id>/`: `instructions/`(챕터별 작성 지시문), `scenes/`(영상 장면 목록), `learner-state.jsonl`, `whisper/`(재전사 결과), `log.txt`. 요약 JSON의 `outputs`가 이 폴더 안을 가리킨다. 지표 셋(완료율·오류율·소요 중앙값)은 전부 이 파일들의 집계다.

## 12. `ops/STATUS.md` — 상태 보드 (생성 형식)

사람이 고치지 않는 자동 생성 마크다운. 구조는 고정:

1. 머리말: 생성 시각, 생성한 도구, "직접 수정 금지" 문구
2. **교재 표**: 제목 | 상태 | 기계/문장/섹션/수동 게이트 | 지문 일치 | 마지막 갱신
3. **진행 중 작업**: run_id, 종류, 시작 시각, 현재 단계
4. **최근 실행 10건**: 결과와 소요 시간
5. **다음 할 일**: 각 교재 `progress.json.next_actions`의 취합
6. **용량과 한도**: 미디어 총량/10GB, 월 빌드 횟수/500

CI는 보드를 다시 생성해 차이가 나면 실패시킨다.

## 13. `canPublish` 판정 입력표

판정 함수 하나가 읽는 모든 값의 출처다. 이 표 밖의 값으로 판정하지 않는다.

| 조건 | 근거 파일과 필드 |
| --- | --- |
| 기계 검사 통과 | `machine-check.json.pass == true` |
| 기계 검사 유효 | `machine-check.json.inputs[].sha256` == 현재 파일 지문, `standards.*_sha256` == 현재 기준 지문 |
| 문장 검수 무결점 완주 | `sentence-review.json.status == "clean_pass"` (예외 승인분 반영) |
| 문장 검수 유효 | `source_sha256` == 현재 본문 지문, `protocol.*_sha256` == 현재 기준 지문 |
| 섹션 검수 통과·유효 | `section-review.json` 같은 방식 + 각 판정의 `context.prior_chapters` 지문 일치 |
| 수동 검토 완료 | `manual-review.json`에 `grade: block`이면서 `pending`인 항목 0 |
| 권리 검토 잔여 0 | MR05가 `done` 또는 사유 있는 `waived` |
| 미디어 업로드 완료 | 모든 `media.json.items[].url` 존재 (활성 항목 기준) |

반환은 `{ ok: boolean, reasons: string[] }`이며, `reasons`는 사람이 읽을 문장으로 — 발행 버튼과 명령이 그대로 보여 준다.
