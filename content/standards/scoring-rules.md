# 채점 기준

> 기계 검사가 찾아내는 결함의 목록과 각 결함의 등급이다. 기계 검사는 생성 모델을 부르지 않고 파일을 규칙으로만 훑는다. 그래서 빠르고, 매번 같은 결과가 나오며, 게이트의 기준선으로 쓰기에 적합하다.

---

## 등급은 둘뿐이다

| 등급 | 뜻 | 발행 |
| --- | --- | --- |
| 차단 | 반드시 고쳐야 한다 | 막는다 |
| 경고 | 관리자가 보고 판단한다 | 막지 않는다 |

**차단 항목은 예외 승인 대상이 아니다.** 문장 검수의 심각 등급은 사유를 적고 넘길 수 있지만 기계 검사의 차단은 그럴 수 없다. 사람의 판단이 갈릴 여지가 없는 것들만 차단으로 넣었기 때문이다. 출처가 비어 있는 것을 "그래도 괜찮다"고 판단할 여지는 없다.

정적 검사와 구조 검사는 **항상 함께 실행하고 결과를 하나로 합친다.** 한쪽만 통과한 상태를 통과로 기록하지 않는다. 따로 돌리면 한쪽만 통과시키고 배포하는 일이 생기고, 그러면 다른 쪽 결함은 끝까지 남는다.

---

## 정적 검사

파일에 무엇이 있고 없는지를 본다.

| 항목 | 무엇을 찾는가 | 등급 |
| --- | --- | --- |
| 필수 항목 누락 | 교재 정보 파일에 정의된 필수 항목 중 비어 있는 것 | 차단 |
| 출처 주소 누락 | 참고 자료 기록에 접근 위치가 없는 것 | 차단 |
| 출처 확인 시각 누락 | 언제 확인한 자료인지 없는 것 | 차단 |
| 사용 조건 누락 | 그 자료를 써도 되는지 기록이 없는 것 | 차단 |
| 표기 의무 미이행 | 사용 조건이 출처 표기를 요구하는데 화면에 표기가 없는 것 | 차단 |
| 미디어 사용 사유 누락 | 이미지나 음성이 왜 쓰였는지 기록이 없는 것 | 경고 |
| 미확인 문구 잔존 | 확인하지 않았거나 추정값이라고 본문이 스스로 밝힌 표현이 남은 것 | 차단 |
| 채점 기준 미비 | 이 문서 자체가 없거나 항목이 비어 있는 것 | 경고 |
| 수동 검토 미해결 | [수동-검토-항목](manual-review-items.md)의 차단 항목이 처리되지 않은 것 | 차단 |
| 대체 설명 누락 | 인포그래픽에 대체 설명이 없는 것 | 차단 |
| 자막 또는 요약 누락 | 개요 영상에 자막도 텍스트 요약도 없는 것 | 차단 |

미확인 문구 잔존을 차단으로 둔 이유는 이것이 **AI가 만든 글에서 가장 흔하게 남는 흔적**이기 때문이다. 실제로 확인하지 않은 것을 확인한 척 쓰는 것보다는 나은 습관이지만, 그 표현이 그대로 학습자에게 나가면 교재의 신뢰가 통째로 흔들린다.

대체 설명과 자막을 차단으로 둔 것은 접근성이 첫 출시 범위에 들어 있기 때문이다. 색 대비 전수 점검처럼 다음 출시로 미룬 항목은 여기 없다.

## 구조 검사

파일 전체를 훑어 앞뒤가 맞는지를 본다. 문장 하나만 봐서는 알 수 없고 전체를 봐야 잡히는 것들이다.

| 항목 | 무엇을 찾는가 | 등급 |
| --- | --- | --- |
| 지키지 않은 예고 | 뒤에서 다룬다고 해 놓고 어디서도 다루지 않은 것 | 차단 |
| 없는 것을 가리키는 회수 | 앞서 다뤘다고 하는데 실제로 앞에 없는 것 | 차단 |
| 시제 뒤섞임 | 같은 대상을 가리키는 표현의 시제가 섞인 것 | 경고 |
| 문장 중복 | 긴 문장이 서로 다른 섹션에 그대로 반복된 것 | 경고 |
| 용어 표기 흔들림 | 같은 개념을 서로 다른 표기로 부르는 것 | 경고 |
| 섹션 순서 역전 | 뒤 섹션에서 정의한 용어를 앞 섹션이 쓰는 것 | 차단 |

앞의 두 항목이 이 검사의 핵심이다. **긴 글을 나눠서 생성하면 반드시 생기는 종류의 결함**이고, 문장 단위 검수로는 절대 잡히지 않는다. 문장 하나만 보면 "뒤에서 자세히 다룬다"는 완벽하게 정상적인 문장이기 때문이다.

섹션 순서 역전을 차단으로 둔 이유도 같다. 학습 교재에서 순서가 뒤집히면 그 지점부터 뒤가 전부 안 읽힌다.

---

## 검사 대상과 제외 대상

**대상**: 학습자가 화면에서 보게 될 모든 것. 제목, 산문, 목록 항목, 인용, 표의 행.

**제외**: 머리말, 코드 블록, 주석. 코드 블록을 제외하는 이유는 코드에는 이 기준의 대부분이 적용되지 않기 때문이다. 다만 코드 밖의 산문이 코드를 설명하는 부분은 대상이다.

---

## 매번 처음부터 다시 판정한다

기계 검사는 이전 판정을 재사용하지 않는다. 실행할 때마다 현재 파일 기준으로 처음부터 다시 본다.

문장 검수는 회차와 무효화 규칙이 복잡하지만 기계 검사는 그렇지 않다. 빠르고 결과가 매번 같으므로 아낄 이유가 없고, 아끼려 들면 **낡은 판정이 남아 있는 상태**가 생긴다. 그게 게이트가 실제로는 막지 못하면서 막는 척하는 가장 흔한 경로다.

관련 규칙은 [검수-프로토콜](review-protocol.md)에, 사람이 봐야 하는 항목은 [수동-검토-항목](manual-review-items.md)에 있다.
