# 오픈코스 생성 스킬

교재 한 권은 12단계(S1~S12)로 만들어진다. 단계 설계의 정본은 `docs/10-생성-파이프라인.md`,
파일 계약의 정본은 `docs/11-콘텐츠-계약-스키마.md`다. **경로·상태 전환·임계치·기록·검증은
결정적 도구가 지키고, 글·그림·대본을 쓰는 것이 에이전트의 일이다.**

## 세션을 시작하면

1. `ops/STATUS.md`를 읽는다 (없으면 `pnpm course status <슬러그>`로 교재별 확인)
2. 사용자에게 **셋만** 보인다: 지금 어느 단계인지 · 다음에 가능한 일 · 그중 권하는 일
3. 단계 이름을 외우게 하거나 이전 세션을 되짚게 만들지 않는다

## 명령

```bash
pnpm course create --title <제목> --topic <주제> --audience <대상>   # S1
pnpm course preflight --sections N --chars N --seconds N            # S4 임계치 점검
pnpm course register <슬러그>                                        # S12 초안 등록 (전부 아니면 무)
pnpm course status <슬러그>                                          # 상태·게이트·다음 할 일
pnpm check <슬러그>                                                  # 기계 검사 (정적+구조, 파일로 기록)
pnpm course publish <슬러그> | hide <슬러그>                          # 게이트 확인 뒤 상태 전환
```

## 단계별 규칙

- **S2 자료 수집**: 출처마다 `url`·`fetched_at`·`license`를 수집 시점에 함께 적는다.
  실제로 열어 본 자료만 등록한다. `review/source-map.json` 계약을 따른다.
- **S3 목차 승인**: 제안 → 사용자 편집 → 승인. **승인 전에는 어떤 생성도 시작하지 않는다.**
  승인되면 `course.json`의 chapters를 확정 구조로 교체한다.
- **S4 실행 전 점검**: `pnpm course preflight`. 하나라도 걸리면 분할하거나 보류한다.
- **S5 루브릭·지시문**: `review/rubric.json`과 챕터별 작성 지시문(`ops/runs/<run>/instructions/`)을
  스타일 버전(`content/standards/styles/`)과 초보자 기준에 맞춰 쓴다.
- **S6 본문 초안**: 소단원 하나당 생성 호출 한 번. 문맥은 **작성 지시문 + 앞 챕터들의 확정
  요약만** — 뒤 챕터를 미리 보지 않는다. 확인 못 한 사실은 그대로 적는다(기계 검사가 잡는다).
  본문에서 미디어는 **식별자로만** 참조한다 (`fig-01`, R2 URL 직접 기입 금지).
- **S7 인포그래픽**: 디자인 시스템 토큰으로 HTML 저작 → PNG 렌더 → `alt`와 `purpose`를
  media.json에 기록. alt 없는 인포그래픽은 산출물이 아니다.
- **S8~S10 영상**: 장면 목록(장면 = 시각 정의 + 나레이션 한 문장, 챕터당 ≤90초) →
  장면별 TTS(Qwen3-TTS) → Whisper 재전사 유사도 ≥0.65 검증(불합격 장면만 재합성) →
  길이 실측으로 timeline.json + captions.vtt + 챕터 mp3.
- **S11 업로드**: 모든 미디어가 로컬에서 완성·검증된 뒤 **일괄** 업로드하고 URL을
  media.json에만 기록한다.
- **S12 등록**: `pnpm course register`. 하나라도 빠지면 등록되지 않는다 — 그게 정상이다.

## 검수와 발행

초안 등록 뒤: 기계 검사(`pnpm check`) → 문장 격리 검수 → 섹션 검수 → 수동 검토 →
`pnpm course publish`. 문장 검수 규칙은 `content/standards/review-protocol.md`가 정본이며,
검수자는 매번 새로 시작한 서브에이전트다 — **원문 전체·이웃 문장·다른 판정을 절대 주지 않는다.**

## 지키는 것

- 검수 판정 파일을 손으로 고치지 않는다. 도구가 쓴다
- 상태 값을 직접 발행으로 바꾸지 않는다 (빌드가 어차피 거른다)
- 모든 실행은 `ops/runs/`에 기록된다. 실패한 챕터는 실패한 단계부터 재개한다
- 계약을 바꾸려면 `docs/11`을 먼저 고친다
